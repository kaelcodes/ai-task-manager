# v0.2 — Module 1: Native Windows Notifications

**Status:** COMPLETE — BUILD-VERIFIED AND RUNTIME-VERIFIED (user-confirmed)
**Date:** October 12, 2026

## Scope

Deliver native Windows OS notifications for existing task reminders, with a 15-minute snooze — reusing the existing reminder engine. No second reminder engine, no database, no new reminder rules, no cloud/mobile/background service.

Delivered:
- **Windows OS notifications** for due-today / overdue reminders while the app is running.
- **15-minute snooze** per reminder: hides it from the in-app banner and suppresses its OS notification for 15 minutes, then it becomes eligible to show and notify again if still due.
- **Per-session deduplication**: each reminder notifies at most once per app session (guarded by id), immune to React rerenders, the 60-second refresh tick, and task refreshes.
- **In-app banner preserved** exactly as before.
- **Graceful permission handling**: permission is requested lazily on first deliverable reminder and cached; denial or any delivery error is swallowed so in-app reminders keep working.

## Architecture

- `scheduling.ts` (`computeReminders`) — unchanged; remains the single source of reminder rules.
- `src/services/notifications.ts` — **new** delivery module, the only code that talks to the OS notification API (`isPermissionGranted`, `requestPermission`, `sendNotification`). Delivery is kept separate from calculation so a future mobile/other backend can replace just this file.
- `src/services/useReminders.ts` — wires delivery into the existing hook: a `notifiedIds` ref dedupes per session; a `snoozed` map (id → expiry ms) filters `active`; `snooze(id)` sets a 15-min expiry and clears the notified-id so the reminder can re-notify after expiry. Snooze/dismissal are in-memory only (reset on app restart).
- `ReminderBanner.tsx` — consumes the same hook; added a per-reminder **Snooze** button alongside the existing dismiss.

## Limitations

- **Running-app only** — no notifications while the app is closed (closed-app/background delivery remains future work).
- **Snooze and dismissal reset on app restart** (in-memory, not persisted) — by design for this module.
- Same-session duplicate-prevention and dismissal edge cases were not separately retested in this pass (they were verified when first implemented).

## Future work

- Closed-app / background reminders (native Windows scheduling).
- Optional persistence of snooze/dismissal across restarts.
- Mobile delivery reusing the same `computeReminders` rules (swap only `notifications.ts`).
